## 2. The Rs 0.05 — exact trace (req 21–23)

```
milk_collections.amount  ← importer wrote qty × rate WITHOUT rounding
  486 / 864 rows have >2 decimals (e.g. 481.7367, 11788.525)
        │
        ├─ SIDE A (ledger):  each row → round2(c.amount)  → Σ → round2   = 514,439.18
        │     company_ledger.js:161 (row) + :349 (total)
        │
        └─ SIDE B (summary): round2(SUM(raw))                          = 514,439.23
              accounting.js getMilkCostSummary → consumed by
              P&L total_expenses (financial_reports.js:149)
              → expense rows 647,569.18 ≠ 647,569.23
              → net −2,635.15 ≠ −2,635.20
```

**Authoritative amount = 514,439.18** (per-row/paisa rounding): the ledger *displays*
individual collection rows at 2 decimals, so the total must be the sum of what is
displayed. Policy adopted: *every milk-collection aggregate is Σ round2(row), and new
rows are stored at 2 decimals.*

## 3. Gross Margin/L — exact trace (req 27–30)

```
Gross Margin/L = (net milk sales − lot COGS) ÷ net milk litres
                 getDailySalesRealization (dairy_costing.js:309-382)
net sales       = milk sale lines − invoice discount − milk returns   ✓
denominator     = milk sale litres only (not raw collection litres)    ✓
lot COGS        = Σ lot_consumptions WHERE reference_type='sale'       ✗ = 0
                     because stock_lots = 0, lot_consumptions = 0,
                     lot_cutover_date unset → UI posted all 82 batches
                     through the non-lot path (production.js saveProductionBatch)
```

Formula and denominator are correct; the **cost side is structurally zero** until the
existing lot engine is activated (cutover + opening lots). Until then the UI must say
so instead of printing an inflated margin.

## 4. Decisions (no duplicate engines)

1. **One rounding policy** for milk money: round each collection row to paisa, aggregate rows. One source: `getMilkCostSummary`.
2. **One date layer**: extend `getDatePreset` (renderer) — yesterday / last_7 / last_90 / all — plus one shared preset-bar helper reused by Bank, Cash Deposit, Advances, Stock Statement.
3. **One stock period engine**: `getStockLedger` gains summary buckets + time/labels; Stock Statement UI consumes it. `getStockStatement` stays the current-valuation view it already is.
4. **One daily factory report**: `getDailyReconciliation` extended (shift split, purchases), not replaced.
5. **Lot engine activated, not reinvented**: existing `setLotCutover` + `createOpeningStockLots`; history never back-costed (req 32).
6. **No ≈ tolerance changes** — both sides of every check compute the same expression.
