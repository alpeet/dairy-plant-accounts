## 3. Defect found and fixed — the diesel payment was expensed twice (Rs 60,089)

**The workbook records the same payment in two registers with two different dates:**

| Workbook row | Sheet | Date column | Amount |
|---|---|---|---:|
| `Expenses` r46 | expense register | 66992 → **2083-05-31** | 60,089 |
| `BANK RECON` r105 | bank statement | 67011 → **2083-06-19** | 60,089 (QR-089) |

One payment: `bank_transactions` has exactly one Rs 60,089 debit (id 115, `supplier_payment`,
"already reflected in ledger"). The importer de-duplicates expense vouchers on **date + amount**,
so where the two rows agree it books one voucher — here the dates differ by 20 days, so **both**
were kept (`PC-0171` at 2083-05-31 from the register, `PC-0091` at 2083-06-19 from the bank
statement) and operating expenses carried the diesel twice.

**Fix:** `scripts/audit/fix-petty-bank-duplicate.js`
(dry-run by default, `--apply` writes).

* Backup first: `data/backups/dairy-plant.db.bak-petty-bank-dup-2026-10-25T04-03-46`
  (verified: 227 petty rows, 2 diesel vouchers, 120 bank rows — the pre-change state)
* Deleted `petty_cash` id 2662 (the bank-statement copy, 2083-06-19); kept id 2742
  (the register copy, 2083-05-31, the row that matches the workbook)
* `audit_log` row 127 records the delete with the full old row
* Evidence: `docs/audit-evidence/petty-bank-duplicate-2026-10-25T04-03-46.json`
* Bank cash movement untouched (`bank_transactions` id 115 stays)

|---|---:|---:|

## 4. Audit tooling corrected (the false alarms this round exposed)

These printed scary differences that were artefacts of the checks, not of the data:

1. **Sales check skipped rows with no invoice number** — it reported a phantom Rs 134,620 gap.
   It now includes the 23 internal-issue rows and the rent income line, and reports the OPN
   opening documents as their own explained line (workbook P&L includes them in revenue; the app
   correctly does not).
2. **The expense-register check compared both sheets against one database figure**, so the
   register check could never pass. It is now a membership match (amount + description, never date,
   because the bank statement copies two rows with a different date): **87/87 rows have a voucher**,
   plus separate lines for the salary register (12/12) and the INVESTMENT rows (6/6).
3. **The collection check excluded `ADVANCE RETURNED` rows** and then attributed the gap to a vague
   cause. It now counts them, and the rent receipts (Rs 8,695) are checked on their own line.
4. `reconcile-records.js` printed *"the importer only accepts `Salary Advance`, so this sheet is
   currently skipped"* — false since `shared/excel-import.js` accepts `Salary Advance`,
   `Salary_Advance` **and** `Salary`; payroll imported 12/12. Note corrected.
5. `fix-petty-bank-duplicate.js` now backs up through better-sqlite3's backup API — a plain
   `copyFileSync` silently misses the `-wal` file and hands back a stale snapshot.

### The workbook's own net-profit formula is wrong

`C28 = C17 − −C20 − C22 − C21` — a double minus on `C20` **adds** the petty-cash register back
instead of charging it, while `C26` (its own "TOTAL EXPENSES") includes it:

* charges: office 404,114.80 + salary 164,500 − petty 36,921 = **531,693.80**
* states: `C26` = **605,535.80**

So the printed **100,531.92 is 73,842.00 higher** than the workbook's own expense total allows;
with `C26` the workbook would print **26,689.92**. The app charges every register once, so
app − workbook(corrected) = **−149,673.57**, and the three sections above sum to exactly that
(−586,539.37 + 546,256.13 − 109,390.33).
